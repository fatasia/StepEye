## 0. 两条路线的关系

| | 实时规则路线(已做:sop-vision) | 拍照即检路线(参考系统,V 系列) |
|---|---|---|
| 触发 | 持续视频流 | 巡检员拍照、定点相机定时上传、批量上传 |
| 样本需求 | 规则 + 现场标定,部分场景要训练 | 提示词 + 每场景最多 3 张 OK / 3 张 NG 参考图,不训练 |
| 速度 | 毫秒到百毫秒 | 秒级到数十秒,异步排队 |
| 适合 | SOP、人车、持续监控 | 巡检、点检、首件检、低频场景 |
| 主要弱点 | 换型要调规则 | 大模型会判错、会编造、结果不稳定 |

结论:两条路线**共用同一套告警闭环、认证和看板**;"拍照即检"先跑起来积累误报样本,成熟后转实时检测器。

## 5. 无数据起步策略(用户当前没有图片数据)

1. **代理样本**:从 `test-videos/` 两段 CC BY 视频抽多位置帧,做 V0/V5 的判定链路验证(已抽 1 帧实测)。
2. **自拍样本**:巡检类场景(手套、安全帽、烟火)用手机自拍照即可起步,零外部依赖。
3. **客户样本**:向锂电联系人定向要「极耳翻折 / Pack 涂胶」各 3 OK + 3 NG——这是 V5 唯一拿代理样本替代不了的部分。
4. **公开数据集**:MVTec AD 等禁止商用,只可用于内部评测参考(见 README 许可说明)。
5. **纪律**:评测集建好之前,**不对客户承诺任何准确率数字**(指针表读数、首件缺陷尤甚)。
