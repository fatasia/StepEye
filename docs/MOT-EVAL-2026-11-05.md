# MOT-EVAL-2026-11-05：StepEye ClassAwareIoUTracker 公开真值评测（MOT16）

对 `sop-vision/visual/tracking.py` 的 `ClassAwareIoUTracker`（83 行，纯 IoU 关联、无运动模型/外观）用 MOTChallenge 官方真值做两轮公开评测：**GT 输入轮**（测纯关联质量上限）与 **FRCNN 公开检测轮**（测完整链路）。平台代码只读未改；全部数字真实计算，产物可复现（脚本与结果路径见文末）。

## 1. 数据与许可

- **数据**：MOT16 train 官方直链 `https://motchallenge.net/data/MOT16.zip`（无需注册，HTTP 200；Last-Modified 2020-02-18），1,954,509,127 字节与响应头完全一致，CRC 校验通过。仅解压 `train/`（7 序列：MOT16-02/04/05/09/10/11/13，均含 `seqinfo.ini`、`gt/gt.txt`、`det/det.txt` FRCNN、`img1/`）。全部序列 frameRate=30。
- **许可**：MOTChallenge 官网页脚 `rel="license"` 声明数据采用 **CC BY-NC-SA 3.0**（署名-非商业-相同方式共享），允许研究使用。本次评测为内部研究用途，符合许可。
- **协议权威依据**：GT 类别语义与 distractor 预处理依 TrackEval 对官方 devkit 的复刻（`trackeval/datasets/mot_challenge_2d_box.py`）：评测目标 = class 1（pedestrian）且 conf 列=1（"计入评测"标记）；class 2/7/8/12 为 distractor（person_on_vehicle/static_person/distractor/reflection）。

## 2. 协议

- 每序列独立 `tracker.reset()`，`ts = frame/30`。参数用默认 `ttl_s=1.0, max_tracks=256`，`min_iou` 跑 0.3（默认）与 0.5（对照）两组。
- **GT 输入轮**：`gt.txt` 中 class==1 且 conf==1 的框逐帧作为 `Detection(label='pedestrian', confidence=1.0)` 喂入。共 110,407 个目标框、517 条轨迹。
- **FRCNN 公开检测轮**：`det.txt`（FRCNN）按 **conf≥0.5 过滤原始列**后喂入（label='pedestrian'，conf 用检测自身值）。MOT16 FRCNN det.txt 分数**未归一化**（常见 >1）：79,790 行中保留 31,600 行（39.6%），其中 21,604 行 >1 在构造 `Detection` 时钳到 1.0——匹配只用 IoU，钳制不影响关联结果。检测召回聚合 27.4%。
- **计分**：motmetrics 1.4.0（独立 venv，Python 3.12），iou 距离阈值 0.5（等价官方 IoU>0.5），CLEAR-MOT + ID 指标，MT/ML 80%/20%。OVERALL 为 motmetrics `compute_many(generate_overall=True)` 跨序列聚合（自动偏移帧号、避免 id 冲突）。
- **坐标语义（重要修正）**：MOT GT 大量目标框带负坐标（出画部分，官方协议不过滤坐标；MOT16-04 有 9,935 条、占 21%）。评分 GT 保留**官方原始框**；喂入按 `Detection` 契约（平台代码，只读）裁剪到画面内。裁剪框与原始框 IoU<0.5 的框共 4,989 个（4.5%）——这些目标无论关联多好都会产生成对 FP/FN（结构性可见性惩罚，下表单列）。为隔离该伪影，GT 轮另计 **assoc 变体**：喂入=评分=裁剪框几何一致（FP=FN≈0），IDF1/IDSW 即纯关联质量。
- **distractor 预处理对照**：det 轮另算 `preproc` 变体——预测框与 distractor GT IoU≥0.5 时剔除再计分（对齐 TrackEval 默认/官方协议）。

## 4. 与文献参考值对比（定性）

| 参照 | 数据/检测 | MOTA | IDF1 | IDSW | 来源 |
|---|---|---|---|---|---|
| SORT（Kalman+匈牙利） | MOT16 验证集（02/05/09/11）+ 自备 FrRCNN(VGG16)，prob>50% | 34.0 | — | 274 | arXiv:1602.00763 Table 1（PDF 全文核对） |
| SORT | MOT16 test + DPM | 33.4 | — | 1001 | 同上 Table 2 |
| IOU tracker（纯 IoU 关联，最可比） | MOT16 train + FRCNN det.txt | 49.7 | 21.0 | 716 | github.com/bochinski/iou-tracker README |
| ByteTrack | MOT17 test + 公开检测 | 67.4 | 70.0 | 1331 | arXiv:2110.06864 Table 12 |

定性结论：

1. **det 轮 MOTA 不宜与文献直接横比。** 任务规定的"conf≥0.5 过滤"作用在 MOT16 FRCNN det.txt 的未归一化原始分数上，只保留 39.6% 检测、召回 27.4%；而 IOU tracker 官方仓库的加载器**不做输入过滤**（`sigma_l=0` 允许低分检测延续轨迹、`sigma_h=0.5` 只做轨迹初始化），其 MOTA 49.7 隐含召回 ~52%。我们的 25.5 主要反映检测供给不足（FN=80,154 占错误的 97%），不是关联缺陷。
2. **IDF1 30.4 vs IOU tracker 21.0 方向性有利。** 在更少的检测供给下（更高的检测精度、更低的召回），我们的 IDF1 高出 ~9 个点，主要来自 `ttl_s=1.0` 的候选保留（30 帧内重接，SORT 的 TLost=1 帧和 IOU tracker 都没有）——代价是 IDSW 798 略高于 IOU tracker 在更强检测下的 716（不可比，仅记录）。
3. **纯关联上限处在合理位置。** GT 轮 assoc OVERALL IDF1 94.4 / IDSW 1299：静态相机序列接近满分（04=100、11=98.0、02=98.6、09=92.0），难例显著退化（05=89.4 交叉人流、10=86.5 相机运动、13=74.2 夜间密集+相机运动）。退化机制主要是**静默 id 碎片化**——MOT16-13 的 IDFP=3027 远大于 IDSW=872：IoU 断链后新轨首次接手不触发 CLEAR-MOT switch 计数，但全局 id 映射已碎。
4. **类感知机制未被本基准激励。** MOT16 是单类（pedestrian）协议，所有 label 相同，class-aware 匹配退化为普通 IoU 匹配；本评测度量的是 IoU 关联核心，不是类别门控。

## 5. 限制

- **GT 输入轮的乐观性**：检测完美（无 FP/漏检、conf=1），测的是关联上限；真实链路受检测质量支配（det 轮 FN 占 MOTA 损失 97%）。
- **坐标契约裁剪**：`Detection` 要求框在画面内（平台契约，未改动），出画 GT 裁剪喂入在 official 语义下产生 4,989 成对 FP/FN；已用 assoc 变体隔离并逐序列量化（T2"结构性FP"列与风险框数几乎完全吻合）。
- **conf 过滤协议差异**：MOT16 det.txt 分数未归一化，"conf≥0.5"语义敏感；21,604 行 >1 钳到 1.0 仅为满足契约（匹配只用 IoU，无影响）。与文献的 det 轮数字存在检测子集差异。
- **motmetrics vs 官方 devkit**：IoU≥0.5 与官方 >0.5 的边界差异可忽略；官方 distractor 预处理已补为 preproc 变体（FP 1347→1183，影响很小）；MT/ML 80/20 定义一致。
- **单类基准**：class-aware 门控未被激励（见 4.4）。
- **未覆盖**：MOT17 三套检测（其 FRCNN D-34 检测更强，可作后续）、多类场景、HOTA 指标（motmetrics 不提供）。

## 6. 建议

1. **值得引入轻量运动外推/门控**。GT 轮证据明确：无运动模型的静态 IoU 在相机运动（10）与交叉/密集（05/13）场景 id 碎片化。最小改动是在关联前对 track 的上次框做单帧常速位移预测（dt 已知，速度可由最近两次观测差分），或对高分对增加中心距离门控；预期收益集中在 05/10/13（assoc IDF1 89.4/86.5/74.2 → 潜在 +3~10 点）。这与 SORT 采用 Kalman+匈牙利而非纯静态 IoU 的动机一致。
2. **贪心匹配可升级为全局最优**。现实现对 (-IoU, tid, j) 贪心抢占，拥挤时局部次优；换 `scipy.optimize.linear_sum_assignment` 是低成本改动（同样只改平台代码时另行立项，本评测不改动平台）。
3. **min_iou 维持 0.3**，勿调 0.5（T4）。
4. **ttl_s=1.0 的候选保留是该跟踪器对同类的真实优势**（IDF1 高于 IOU tracker 的机制），建议保留并作为卖点记录。
5. 后续如需更强激励，可在 MOT17 公开检测（D-34）上复跑同一脚本（`--root` 指向 MOT17/train 即可）。
