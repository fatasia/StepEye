# 巡检巡防方案(StepEye)

> 2026-11-03。基于现有平台能力(全部已落地组件)组合出的巡检/巡防完整方案,标明每块的状态。

## 一、总体架构

```
摄像头(RTSP/GB28181/ONVIF)
   │
   ├─→ Monibuca(流媒体:WebRTC 预览 0.5s / MP4 录像 R3 / ONVIF 发现 / GB28181 信令)
   │        │ rtsp 转发
   │        ▼
   └─→ StepEye visual-server(exe)
         ├─ 实时规则线:安全规则常驻执行器(S4 跌倒/S16 无人值守/S17 聚集/S15 手机/S1 禁区)
         ├─ 拍照即检线:定时巡检任务 → VLM/AnomalyDINO 判定 → 结构化结论
         ├─ 告警中心:三源汇入 → 飞书推送 → 处理闭环 → 误报复核回流
         └─ GIS 厂区图:平面图打点 + 经纬度地图 + 告警点位闪红
```

## 二、巡检(定时主动检查)

| 场景 | 判定 | 状态 |
|---|---|---|
| 设备点检(表盘/液位/阀门状态) | 拍照即检 gauge 模板 | ◐ 引擎可用,评测集先行 |
| 台面 5S / 工具归位 | housekeeping 模板 | ◐ 引擎可用 |
| 包装箱破损 / 标签 | package_damage / label_check 模板 | ◐ 引擎可用 |
| 外观异常(划痕/污染) | **AnomalyDINO(1-8 张好品图)** | ✅ 引擎已落地(本轮) |
| 巡更到位 | person_present 按时段规则 | ◐ 规则可配,专用 UI 未做 |

巡检执行形态:①巡检员手机拍照上传(APP/网页)②定点相机定时抓图上传(`tools/cam_uploader.py`)③Monibuca 按计划抓帧推送。三条路都汇进同一个检测队列与告警中心。

## 四、部署形态(轻量,两个 exe)

```
visual-server.exe  (平台:分析/告警/看板/向导)
monibuca.exe       (流媒体:ONVIF 发现/GB28181/WebRTC 预览/MP4 录像)
+ configs/         (工位与场景配置)
```

- Monibuca 配置模板见 `deploy/monibuca/config.yml`:rtsp 拉流转发、webrtc 预览、record 录像(R3)、
  onvif 发现、gb28181 信令(国标客户启用)。
- StepEye 的工位 source 指向 Monibuca 转发的 RTSP;浏览器预览走 Monibuca WebRTC(0.5s 延迟)。
- GIS:GB28181 设备目录经纬度 → `/api/cameras/gb28181/sync` 自动入图;室内用平面图打点。
