## 1. 结论（先说）

1. **负载维度判级（预注册判据，官方留出口径）：三个负载全部"可用"。** 逐负载 argmax 准确率 20=0.9615 [0.870,0.989]、40=0.9808 [0.899,0.997]、neg40=0.9808 [0.899,0.997]（Wilson 95% CI，n=52/负载）；负载间最大差 +1.9pp，CI 大量重叠，**未见负载维度塌陷**。平台口径（只输出单例候选集标签）acc 0.942/0.904/0.962。
2. **但"对未见负载可用"这句话本身不成立，不能这么说。** 部署 ONNX 训练时见过全部三种负载（train 389 条覆盖 20/40/neg40：130/129/130 条），语料里不存在"模型没见过的负载"。本实验验证的是**同一负载内新记录（repeat 9-10 留出）的逐负载表现是否一致、置信度是否漂移**，即对平台"覆盖六种负载/轨迹"声明的分层审计——不是新负载泛化证明。真·跨负载泛化在该 ONNX + 该语料上**不可检验**（无重训链路，留负载重训做不了）。
3. **全部 8 个全语料错误都是"漂移性误判为 spalling"，负载不是主要维度。** 错误集中在 3 个工况的晚批次记录（backlash/trap/20 会话1 的 repeat 6–10 连续 5 条全错；normal/trap/40 的 rep8,10；backlash/sin/neg40 的 rep9）。78 个工况中仅 10 个出现晚批次 p_spalling 跳变 >0.05（中位跳变≈0）。**主风险是单次录制会话内的时间性漂移，三个负载上机制相同。**
4. **类别层面严重不均衡：lack_lubrication 与 spalling 全语料 0 错误；backlash 是脆弱类**（test 口径逐负载召回 0.75/1.00/0.875），弃权机制只能拦住一半漂移错误（test 桶 8 条 review vs 4 条错误，其中 2 条错误（记录 31、39）拿到 0.85/0.92 的自信错标签，不会被 review）。
5. **每负载 n=52、每格 n=4/8/8/32，本实验只能排除"≥11pp 的负载塌陷"（CI 下界 0.87–0.90），分辨不了 <5pp 的负载差异**；normal/backlash 单类格子的 CI 覆盖 0.30–1.00，对单类下强结论证据不足。与 D1 同口径：**协议可复用（负载留出 + 记录级留出 + Wilson CI + 预注册判据），平台接入不需要改动；建议把 scope 文案改准确。**

## 2. 输入契约与模型（实测）

`ActuatorClassifierService`（`sop-vision/visual/mechanism_actuator_classifier.py`）的输入契约：

| 项 | 值 | 实测核对 |
|---|---|---|
| 类别 | `normal, backlash, lack_lubrication, spalling`（顺序即索引） | 与官方 `records.json` label 字段一致 |
| 输入 | `[batch,2000,3]` float32，输入名 `values`，80 秒完整记录，25 Hz，五段 16 s 周期 | 779 条语料全部 (2000,3)，0 异常 |
| 通道 | 列严格为 `setpoint_mm, error_mm, current_A`，**客户端不做归一化**，归一化在图内 | 实测范围：setpoint 20–140 mm（三种负载同行程）；error −7.42–5.92 mm；current −0.50–1.93 A |
| 负载/轨迹 | `load ∈ {20,40,neg40}`，`profile ∈ {sin,trap}` | 与 .mat key 解析一致，0 冲突 |
| 输出 | `probabilities [N,4]`（行和=1）+ `candidate_set [N,4]` | 行和 1±1.2e-7；多例/空候选集 → `review`，不给默认标签 |

关键点：setpoint 三种负载完全同行程（20→140 mm），负载差异只体现在 error/current 通道——这是负载泛化的物理风险点，也是本实验要量化的问题。

## 8. 同族排查：真正的主风险是"批次内时序漂移"，不是负载

发现一条晚批次错误后，按同机制清剿全语料：

1. **逐 repeat 概率轨迹**（3 个出错的工况）：同一工况内 repeat 1–5（训练段）p_true=0.96+，repeat 6 起 p_spalling 单调爬升直至翻转。例如 `backtrap1st20`：rep1–5 p_spalling≈0.03 → rep6–10 为 0.69/0.57/0.59/0.92/0.85（5 条全错）；`traintrap40`：0.09→0.07→0.76→0.22→0.62（rep8,10 错）；`backsin1stneg40`：rep9 p_spalling=0.63（错），rep10 已回落到 0.12（对）。
2. **按 repeat 桶统计 p_spalling 均值**：normal 0.006(rep1–5)→0.041(6–7)→0.145(rep8)→0.091(9–10)；backlash 0.004→0.076→0.091→0.117；lack_lub 0.000（全程）；spalling 0.93（全程稳定）。错误只出现在 rep6+ 桶（0/2/1/4 条）。
3. **逐工况跳变**（晚批次 p_spalling 均值 − 早批次）：78 个工况中位数≈0，仅 10 个工况跳变 >0.05，最大 3 个见上——漂移集中在少数工况，不是全语料系统性爬升。
4. **弃权与漂移的拦截关系**：rep9–10 桶 156 条中 8 条被 review（拦下记录 29、280 两条错误），但记录 31、39 拿到 0.85/0.92 的自信单例错标签直接放行。**弃权拦截率约一半，不能依赖它兜底。**
5. 该漂移横跨三个负载（20/neg40 的 backlash、40 的 normal），机制与负载无关：疑似录制会话内执行器状态渐变（发热/润滑状态变化等），晚批次信号更接近 spalling 形态。**这也是官方历史 97.4% 的 4 条错误的全部来源。**

## 9. 判级与统计力（诚实边界）

- 预注册判级结果：**负载 20 / 40 / neg40 = 可用**（argmax acc 0.96–0.98、min 召回恰好 0.75 压线、review 1.9–9.6% ≤10%）。
- 必须同时声明：
  - load-20 backlash 召回 CI [0.41,0.93]、load-40 normal CI [0.30,0.95]——**压线值周围覆盖灾难性取值，单类层面不可下强结论**；
  - "可用"的主体是 lack_lub/spalling/正常记录撑起来的；backlash 是全负载共用的薄弱类；
  - 每负载 n=52 只能排除 ≥11pp 的塌陷，<5pp 差异不可分辨；
  - 官方留出与全量自洽共享同一台设备、同一批录制会话，**跨设备泛化完全未验证**（平台 manifest 原本也是这么标注的，本次结论未改变这一点）；
  - "对未见负载可用/不可用"这一问题在本 ONNX + 本语料上**不可检验**（训练已见全负载，无重训链路），任何声称"验证了未见负载泛化"的说法都不成立。

## 10. 对平台的建议

1. **scope 文案改准确**（平台侧一行配置/文档改动）：现文案"Cranfield 已知六种负载/轨迹；上传记录的设备与工况未独立验证"可补一句实测依据——同设备语料内逐负载一致（0.96–0.98），薄弱类是 backlash，主风险是同会话晚批次漂移；工位配置里建议提示"**仅限已见负载 + 已见设备；同会话连续记录需人工抽核**"。
2. **review 工位按负载配预算**：负载 40 约 6–10% 记录会进 review（空候选集弃权），负载 20/neg40 约 2–4%；review 是保护性的（弃权记录错标签率 0），不要把它当缺陷抑制。
3. **不建议依赖弃权兜底漂移**：约一半漂移错误以高置信单例标签放行（0.85–0.92）。若平台有工位级"连续 N 条同类标签则抽核"机制，可把 backlash 类的同会话连续输出列入抽核对象。
4. **后续再训的前置条件**（当前无重训链路，仅记录方向）：需要新设备/新负载点的独立录制（含多批次、跨时长），且训练集必须按**录制会话/批次**留出，而不是按 repeat——否则批次漂移会继续藏在训练记忆后面。数据到位后，本报告的协议（负载留出 + 会话留出双协议）可直接复用为验收门槛。
