# 工位上线向导:用户自助上传资产做 SOP 识别(编排设计)

> 2026-11-03。回答:用户上传「样本+标注」与「文档/图片/视频+标注」做 SOP 识别,如何编排最合理。
> 核心理念:**用户的心智是"让系统学会检查我这个工位",不是"我要上传文件"** —— 所以编排放,
> 是一条向导流水线,不是五个孤立上传页。

## 一、资产 → DSL 映射(编排的骨架)

| 用户上传 | 编译产物 | 落进 DSL 哪里 | 现有地基 |
|---|---|---|---|
| **文档**(作业指导书 PDF/Word) | LLM 编译 → 步骤序列草稿(名称/顺序/foreach/超时) | `steps` | SOP-COMPILE.md 设计 |
| **现场图片** | ①文本圈选→多边形 ②摆状态采集参考图 | `zones` / `roi_states` | 区域编辑器 ✅ / calibrate API ✅ |
| **视频**(作业录像) | 时间轴步骤分段 → ①验证步骤边界 ②抽帧进回归集 ③vlm_check 样本 | `steps` 验证 + 回归集 | run --video ✅ |
| **样本+标注(整图级 OK/NG)** | V5 参考图 / 回归 manifest | `inspection.yaml` + regress | samplegen/samples 页 ✅ |
| **样本+标注(框级 YOLO)** | 训练集 → 微调 | `DetectorCfg.model` | TRAINING.md ✅ |

**编排原则:向导每一步都在写同一份工位 YAML(单一事实源)**——向导不是新存储,是 YAML 的
生成器/编辑器;断点续作 = 项目状态 + YAML 存在性;与热重载天然衔接。

## 二、五步向导(Station Onboarding Wizard)

```
Step0 新建工位 → Step1 文档编译 → Step2 画面与区域 → Step3 证据绑定 → Step4 样本标注 → Step5 验证上线
     (模板/空白)    (草稿+人确认)    (拖框/文本圈选)    (每步选证据方式)   (整图级先做)    (回放+影子+启用)
```

- **Step1 文档编译**:上传 SOP 指导书 → glm-5.3-flash 出步骤草稿 → 用户在步骤列表确认/增删/改序。
  双闸门纪律:LLM 草稿必须人工确认,且过回放验证才生效。
- **Step3 证据绑定**(向导的核心屏):每个步骤一行,证据方式四选一——
  ①手部停留(选区域)②结果核验(摆好状态→点采集)③VLM 判定(写提示词,可用样本页自测)
  ④检测器(选模型文件+类别)——四个后端**全部已落地**,向导只是把它们排成一列让用户填。
- **Step5 验证上线**:上传一段作业视频离线回放 → 步骤甘特图人工核对 → 影子模式按钮(≥2 周纪律)→ 启用。

## 三、三个关键设计决策

1. **视频时间轴标注是最合理的标注形态**(不是让用户画框):
   用户在播放器时间轴上拉区间——"这段是 S1、这段是 S2"。系统自动:①校验 DSL 步骤边界是否自洽
   ②区间内抽帧成 vlm_check 提示词样本 ③抽帧进回归 manifest。标注成本从"理解 DSL"降为"看视频拖鼠标"。
2. **标注分两档,先整图后框级**:整图级(OK/NG)→ V5 参考图/回归集,当天产生价值;
   框级(YOLO txt)→ 训练集,攒够 500 张才触发微调。UI 先做整图级,框级走 X-AnyLabeling 导入转换。
3. **断点续作与草稿态**:项目表存 status(draft→verified→shadow→live),每步完成即写 YAML+落盘资产;
   任意一步可退出,回来从状态续。
