# MOT17 跟踪评测（2026-11-09）

延续 [MOT16 评测](MOT-EVAL-2026-11-05.md) 的同一脚本与协议，在 MOT17 训练集上复跑 `ClassAwareIoUTracker`。只评 FRCNN 检测器序列，避免同一场景被 DPM/SDP 三份检测器重复计权。

## 数据

- 来源：https://motchallenge.net/data/MOT17.zip
- 许可：MOTChallenge 数据页标注 CC BY-NC-SA 3.0；仅本地评测，不进入发行包。
- 归档：5,860,214,001 字节，SHA256 `7b486bb2af5cfedbfabc020511ff933a3edbf12182ce4985eec1a210f20f9e06`；ZIP 完整性检查通过。
- 只提取 7 条 FRCNN 序列的 `gt/gt.txt`、`det/det.txt`、`seqinfo.ini`（8.3MB），不落图像；评测不需要像素。
- 序列：MOT17-02/04/05/09/10/11/13-FRCNN，GT 共 112,297 个行人框。

## 与 MOT16 对比

| 指标（GT 纯关联） | MOT16 | MOT17 |
|---|---|---|
| IDF1 @0.3 | 100.0 | 97.5 |
| IDSW @0.3 | 455 | 465 |
| IDF1 @0.5 | 96.1 | 96.0 |
| IDSW @0.5 | 1,275 | 1,349 |

MOT17 更拥挤、相机运动更多，纯关联 IDF1 从 100 回落到 97.5（IoU 0.3），但仍保持高位；IoU 0.5 下与 MOT16 基本持平。检测轮差距主要来自 FRCNN 检测供给：112k GT 中 54k 漏检（FN），不是关联器单独造成。此结果只证明关联质量与跨序列稳定性，不代表 StepEye 在真实工位的跟踪精度。

## 复现

```powershell
cd .v0/mot-eval
# 只评 FRCNN；--root 指向含 gt/gt.txt 的序列目录
.\venv\Scripts\python.exe run_eval.py --root data17/train --out out17 --only-frcnn
```

产物：`.v0/mot-eval/out17/results.json`（50 组，含 OVERALL）与 `out17/txt/*.txt`。脚本在 MOT16 版本上增加 `--only-frcnn` 与 7 列 MOT17 det 兼容；平台代码 `visual/tracking.py` 未改动。

## 边界

- 仅 MOT17 训练集，未跑 MOT20/test；未做跨检测器（DPM/SDP）或跨分辨率矩阵。
- 检测轮受 FRCNN 输入限制，不能当作平台自带检测器精度。
- 未使用 ReID/外观特征；遮挡与跨相机身份关联不在本评测范围。
