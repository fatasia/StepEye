# 模型质量：冲突标注隔离与戒指诊断

2026-11-04。本轮修复训练前的标签冲突漏检，保留旧数据和所有既有评测；没有重复训练、调测试阈值或做多分辨率对照。

## 已修复：同图冲突标签仍能进入训练

原训练检查只拒绝相同SHA图像跨train/val，没有检查同一集合内的相同图像是否对应不同真值。现在复用已有图像SHA，在加载训练器前比较规范化YOLO标注；冲突报错同时给出两份标签路径。数字格式和行序差异不误判，坐标按1e-6归一化精度比较，不引入Torch/GPU。

旧积水准备脚本自动保留重复组中「有效框最多」的一份标签。这不是消歧：多框不保证正确。新工具 `tools/quarantine_detection_conflicts.py` 枚举源文件各份标签，不替用户选真值；所有冲突图像退出新版本，保留原train/val/test位置。作者空文件没有独立背景确认的两张图也不再作为负样本。

## 戒指R0：排除转换错误，尚未找到已证实的单一根因

核对177图347框的作者原始标注与实际训练YOLO标签，类别顺序一致，归一化坐标最大差仅 `4.98e-11`（10位小数写入误差），没有发现错类或错位转换。

既有固定640输入下，83个训练戒指框的中位宽高约20.5×13像素，75个短边小于16像素；手表与腕带分别约75.8×54.3、68.4×48.6像素。训练戒指框数并不少于手表框数。小目标与模糊是风险因素，**不能直接当作R0已查明的原因**，也没有通过改测试阈值粉饰结果。

证据 `.v0/safety-model-audit/edge-wrist/ring-label-diagnosis-v2.json`。本轮没有重跑腕带推理或训练；戒指识别继续保留未达标状态。
