# 模型发布运行监控

发布后的工位可按运行可用性自动回滚到上一已审批版本。默认关闭，管理员按工位显式启用；不使用检测置信度推断模型精度。

- 只采集实际加载版本的成功帧时间、运行线程状态和错误计数。
- 默认观察30秒、至少5次样本；连续无有效帧，或窗口内错误累计达到3次时尝试回滚。帧过期阈值10秒。
- 回滚前核对上一版本的审批、评测报告绑定和文件SHA。旧权重缺失或被修改时阻断，不退回未知模型。
- 复用服务已有状态心跳，不新增常驻线程。周期进行中先保留待重载状态，待可重载后再确认实际恢复；每次启用记录最多自动回滚一次。

## 接口

`GET /api/model-release-monitor/{scene}` 查询状态；未配置返回404。

管理员通过 `PUT /api/model-release-monitor/{scene}` 配置当前active版本：

```json
{"release_id":"MR-当前版本ID","policy":{"enabled":true}}
```

健康采样只由服务内部生成，没有上传健康指标的HTTP入口。手动激活或回滚也在修改账本前检查目标模型SHA，响应的 `applied_to_runtime` 只在对应版本确实加载时为true。

状态依次为 `monitoring`、`pending_runtime_reload`、`rolled_back`；`blocked` 表示历史版本验证未通过，`superseded` 表示管理员已切换版本。重启会清空未完成观察窗口；已记录的回滚动作不重放。

## 验证范围

相关25项测试通过：真实API审批/激活、两份不同SHA的微型ONNX、自动恢复后的真实推理、权限、篡改拒绝、409延迟重载和退出清理。故障健康状态与时间窗口由测试控制，不是厂区故障实验。断流反映可用性问题，不能据此证明故障由模型造成；精度退化仍需标注回流与固定评测。
