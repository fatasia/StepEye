# 现场上线验收：多源融合与光照治理

这份清单给现场实施、质检和运维使用，决定某个工位是否可以上线，不给整个平台盖“工业级”章。

- 单测通过、协议模拟器通过、真实工位通过，是三种不同证据。
- 阈值先约定再评测；漏检、误报、UNKNOWN 和延迟一起报告。
- 摄像头、规则、模型、信号来源或照明条件变更后，按受影响范围重新验收。
- 无有效画面或有效信号时保留未知，不推断为通过、无人或设备正常。
- Windows / Linux 使用同一业务规则，但分别验证依赖、原生服务、时间与浏览器链路。

## 1. 上线需要三份记录

| 关卡 | 必须留下的证据 | 不能替代它的东西 |
|---|---|---|
| 工程回归 | 目标版本的单测/故障反例结果，权限矩阵，启动/停止/恢复记录 | 页面能打开、工具返回成功 |
| 独立回放 | 固定原始片段与信号日志、独立真值、预先约定阈值、分桶报告、所有 UNKNOWN 的分母 | 训练集结果、模型自己生成的标签、合成图全绿 |
| 目标现场影子 | 相机型号/固件/视角、现场照明与遮挡条件、设备时钟/信号标定、操作员复核、问题闭单及审批 | 本机模拟器、别的工厂的指标、通用 COCO 分数 |

本机故障回归用于验证“坏条件不会被误当正常”；没有目标现场样本时，不填写现场通过率，不签署现场通过。正式影子周期沿用项目已约定的至少两周要求；覆盖不足时继续采集，而不是仅按日历天数放行。

## 2. 每个工位固定一份验收包

至少包含：工位 YAML 与规则指纹、代码提交、模型与类别表哈希、采集软件/依赖版本、相机/传感器标识、标定版本、参考图哈希、原始片段与信号文件哈希、人工真值、回放命令、输出结果和签署记录。原件只读保存，模型建议和人工标签分开。

信号原始值按现场数据策略单独采集；运行审计只记录摘要不等于已经保存了可重放的原始测量。凭据、会话 token 和设备密码不进入验收包。

```yaml
station: SITE-ST01
code_commit: 待填写
rules_hash: 待填写
model_sha256: 待填写
camera_firmware: 待填写
reference_sha256: 待填写
signal_schema_and_calibration: 待填写
capture_interval_and_timezone: 待填写
truth_reviewer_and_revision: 待填写
dataset_manifest_sha256: 待填写
acceptance_policy_revision: 待填写
replay_command: 待填写
engineering_result: 待执行或记录结果
independent_replay_result: 待执行或记录结果
onsite_shadow_result: 待执行或记录结果

```

验收策略须写清每类允许漏检/误报/UNKNOWN、端到端延迟与恢复时间，以及发生未知后的人工处置。本文不替现场编造这些数值。

## 3. T30 多源融合最小场景

| 注入或采集条件 | 应观察到的行为 |
|---|---|
| 正常视觉 + 对应工件的有效设备信号 | 条件在规定时间窗口内同时成立才推进；结果可追溯证据来源、序号、时间与标定 |
| 只收到信号，缺少视觉证据 | 混合视觉规则不能通过；不能用历史画面状态拼接当前信号 |
| 信号重复、旧序号、乱序 | 不重复执行；拒绝或明确处置旧数据，有审计记录 |
| 时间戳过早/过晚、TTL 在排队期间到期 | 不把过期值当当前证据；区分接收成功、消费成功和业务动作成功 |
| 同名信号来自未授权设备或错误工位 | 不满足该规则；逻辑 source 字符串不能替代真实设备身份认证 |
| 新信号质量为 uncertain/invalid | 清除旧有效值的资格，不能保留上次“合格”状态继续判定 |
| AND 条件先后成立但从未同时有效 | 不以永久锁存拼成通过；保留各证据有效期 |
| 两路数据互相冲突、缺测、掉线 | 返回可解释的未知/待复核；不能做未标定的简单加权平均后报通过 |
| 相机断流/重连、设备信号仍持续 | 旧视觉状态失效；安全计时与人员/姿态证据清空，恢复重新去抖和计时 |
| 坏画质期间收到扫码、扭矩等物理信号 | 允许记录信号；视觉条件不能取证，受影响周期不能恢复后洗白为 PASS |
| 服务中断、重启、重复提交 | 不重放已消费的设备动作；未消费数据的丢弃/恢复策略可查 |

真实扭矩值只说明扭矩测量，不自动说明视觉工步或装配质量；扫码同样不能替代物体在位的视觉真值。信号值、单位、精度、延迟和校准证书按实际设备登记。

## 4. T31 光照与画质最小场景

| 采集条件 | 应观察到的行为 |
|---|---|
| 健康画面、已确认参考与静止背景 | 指标稳定；可解释使用了多少背景像素、参考来源和采样时刻 |
| 开灯/关灯、昼夜持续变化 | 固定参考持续报异常，不因等待几秒自动适应成正常；恢复原环境或人工重标定后再恢复 |
| 短闪、叉车灯扫过、临时阴影 | 已观测坏帧立即停止取证；报警/恢复连续确认避免状态抖动，周期保留影响历史 |
| 小区域过曝、过暗或强反光，整图均值仍正常 | 局部 tile/饱和指标能反映异常，不能只看整图均值 |
| 工件/人手进入工作区，背景仍稳定 | 不把工作区正常变化误当环境光漂移；背景不足或被遮住时必须未知 |
| 工作区覆盖全图、静止背景无纹理 | 背景或位移检查返回 unknown；不能把零均值或低相关当健康 |
| 相机移位、遮挡、抖动、失焦 | 不能继续沿用旧标定正常取证；重新固定相机/排障，再按现场流程重标定 |
| 异常边界附近反复变化 | 进入和恢复存在确认窗口与滞回；一次正常样本不能提前解除已确认降级 |
| 人工清空/更换参考 | 坏参考被拒绝；清空后不由下一张异常图自动建参考；记录操作者、参考哈希与时间 |
| 曝光/增益/白平衡被改变 | 现场核对设备参数；没有读取实际参数时，不宣称软件已验证“曝光锁定” |

先实施遮光/补光、固定机位、锁曝光/白平衡，再标定算法阈值。白班、夜班、开关灯、反光/背光按目标工位需要分桶，报告最差桶；合成亮度变化不能代替真实夜班和材质反光。

`quality.every_n` 是抽样策略，不是“每帧都检测”的保证。关键工位宜先用 `every_n: 1` 实测性能；如果降低采样频率，须记录实际 FPS、采样间隔和可能漏采的瞬态。连续确认次数对应的真实时间也需实测，不能由标称帧率推定。

当前画质指标不是颜色计量、相机参数锁定验证或通用光照不变性算法。涉及色差、白平衡和细微外观判定的场景必须另外建立真值子集与合格策略。不要在判定输入前随意加入 CLAHE/自动增亮改变模型分布。

## 5. 原生部署、协议与权限

- **Windows / Linux**：分别验证目标 Python/CPU 的依赖 wheel、中文/空格路径、服务账户目录权限、重启、关闭、断电恢复和浏览器播放。单个系统上的运行成功不能替另一系统验收。
- **当前单进程约束**：每个数据目录只有一个 StepEye 采集进程、每台相机只设一个采集所有者；不要开多个 Uvicorn workers 或让两个实例共用同一目录。帧状态、信号消费、WHEP 会话和计时仍有进程内状态；SQLite WAL 不是分布式协调。该约束需由服务管理落实，不能假设系统已经自动阻止双开。
- **角色**：未登录不能读画面或写业务；viewer 不能改标注、相机、规则和真值；operator 的写范围、设备来源与管理网策略需现场批准。当前全局 RBAC 不能当作已实现按厂区/工位隔离的多租户权限。
- **Web 与流媒体**：生产 Web 使用 HTTPS；Monibuca 管理/信令端口不直接暴露到不受控网络，媒体端口按客户端网段放行。验证会话归属、续租、过期、浏览器异常退出与停止服务后的资源回收。
- **录像**：核对工位与原始 stream 的唯一映射；默认文件名前缀的扁平化有歧义时拒绝调阅。记录 Monibuca 文件名所用时区，不能让 Linux 的 UTC 文件名被当作北京时间。检查损坏/未 finalize 录像、跨片段时间检索、Range 播放及文件越界拒绝。
- **ONVIF**：默认仅 RFC1918 / IPv6 ULA；授权测试网通过 `ONVIF_ALLOWED_CIDRS` 在服务端追加，loopback 也须显式授权。设备域名全部解析结果先检查，再固定 IP；服务 XAddr 不能跳到别的设备，SOAP 不跟随重定向。不要把公网暴露相机当测试资源。
- **ONVIF 依赖限制**：本次检查的是 `onvif-zeep-async 4.3.0`。当前初始设备服务按该库默认 HTTP；HTTPS-only、证书信任与不同固件返回地址须另验。该库默认关闭服务端证书校验，使用 HTTPS 字样不能据此宣称证书已验证；要求可信 TLS 的现场需先补受信证书策略。IPv4/IPv6 的地址校验测试不等于完成两类真机联调。
- **设备信任**：来源白名单和序号检查只解决逻辑数据约束。生产设备接入还需独立凭据、连接器与 source 绑定，以及受控网络/网关；普通业务操作员不应能冒充任意物理测量设备。

## 6. 放行与变更

每次放行写明“适用于哪个工位、哪种相机、哪些时段/光照、哪些产品、哪些设备来源”，附实际失败样例与人工处理方式。版本回滚应能恢复规则、模型、参考与信号标定的完整组合。

以下变更至少重跑受影响回放并视情况重新影子：相机/固件/镜头/位置、帧率或采样频率、灯具/遮光/曝光、模型/提示词/阈值、区域与参考、信号设备/单位/时钟/TTL、数据划分与真值。无法确认影响范围时，不沿用旧通过结论。
