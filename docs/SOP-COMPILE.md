# SOP 编排与泛化:设计稿(vlm_check + 指导书编译)

> 2026-11-02。回答:SOP 痛点是编排难(编码 DSL 成本高)与泛化难(绑死坐标/产品)。解法:LLM 编译初稿 + 判定上移语言层。

## 一、vlm_check 条件类型(泛化的核心,半天级,复用 inspect 管线)

DSL 增加:

```yaml
steps:
  - id: S2
    name: 插接连接器
    evidence: {all: [{vlm_check: {prompt: "画面显示连接器已完全插合", every_s: 2.0}}]}
```

语义:**周期内存在至少一帧**(按 every_s 抽帧)经 VLM 判定为真 → 步骤证据满足。
- ✅ **已实现(2026-11-02)**:`dsl.VlmCheck` + runtime 后台判定线程(不阻塞视频循环,队列限深,
  只判激活步骤,判过即保持)+ engine vlm 求值分支;6 项离线测试,全套 73 过
- 泛化靠语言:换型号改提示词一句话;相机挪位/光照变化无感
- 复用:VLMProvider.inspect;缺凭据时自动停用(不炸其余功能)
- 诚实边界:精度中等(幻觉过杀有实证 1/6),用于语义动作类步骤;刚性特征仍走 obj_state
- **混合编排**:一个 SOP 内 per-step 自选引擎(规则/VLM 快照/训练检测器),DSL 本就是混合条件设计

## 二、指导书 → DSL 编译(编排的核心)

管线:上传作业指导书(文字+照片)→ glm-5.3-flash 解析出步骤序列草稿
(动作句式→条件模板:锁付类→foreach+obj_state;取放类→hand_dwell;检查类→vlm_check)
→ 可视化编辑器拖框微调(V9 向导)→ 回放验证关卡 → 上线。
- 模板库兜底:装配骨架参数化(取料→装配→锁付→检→下料),换型只改参数
- LLM 出错稿是常态:验证关卡(一致性+回放比对)是强制门,不省

## 三、泛化的极限(如实)

相机大挪位仍需重标定(向导降成本不消除);手持大物漏检是感知模型级短板,靠训练腿;
语言判定的精度天花板靠蒸馏腿突破(场景定义不变,引擎底下自动升降级,见 ZERO-TO-MODEL.md)。
