## ① 场景定义与引擎解耦:一次声明,引擎自动升降级

**创新是什么**:用户只写一份「场景声明」(区域 + 判定口径 + 参考图),底下的引擎随数据积累自动升级,场景定义一行不改:
1. **免训练档**(当天可用):VLM 提示词判定 / 规则+标定,精度有天花板;
2. **简化训练档**(数据飞轮):运行中的误报/不确定样本自动回流 → 现有模型预标注(人只点"对/错",不拉框)→ 增量训练小检测器 → 影子模式比对 → 一键发布/回滚;
3. **蒸馏档**(降本):样本攒够后平台自动建议"该场景可蒸馏为边缘检测器"(更快/更便宜/可离线),引擎底下换,用户无感。

三层蒸馏的算力分工见 [ROADMAP-v2 §1](ROADMAP-v2.md):高频毫秒级小检测器 / 中频秒级 Qwen3-VL-2B / 低频 API。

**为什么是代差**:

| 对照 | 它的做法 | 代差点 |
|---|---|---|
| Ultralytics | 一个模型绑定一个应用:换场景=重新标注+重新训练+重新部署;训练脚本是用户的活 | 我们把"场景"从"模型"里拆出来当一等公民;引擎升级对用户透明,训练降为"日常点击确认" |
| 海康 | 算法包绑定自家相机/设备,升级=换设备或换包,用户不掌握场景定义本身 | 场景声明是开放的 YAML(用户可读可改),不与任何硬件锁定 |
| 商业平台(AI-SOP 参考项目) | LSTM+固定时间窗,节拍一变就失效,换产品重标重训;Retrocausal 类绑定第一视角工装 | 事件驱动状态机替代固定时间窗;引擎可换、场景可迁 |

**已有地基**:
- DSL 与引擎:`visual/dsl.py` + `visual/engine.py`,混合条件设计天生支持 per-step 自选引擎(规则 / VLM 快照 / 训练检测器);
- `vlm_check` 条件已实现(runtime 后台判定线程,不阻塞视频循环;全套 73 测试通过,见 [SOP-COMPILE](SOP-COMPILE.md));
- Provider 抽象已落地(`visual/llm_provider.py`,端点/模型/温度配置化,换模型只改配置,ADR-002);
- 安全条件 `person_present` / `person_absent` / `person_count` 进 DSL(`visual/perception/persons.py` + `visual/safety.py`)。

**落地任务**:T2(回归集,升降级的闸门)、T15(训练腿 v1 + 模型上传签名)、T16(数据闭环)、T20(蒸馏管线 + 平台自动建议触发)。

**状态**:**半成品**——DSL / vlm_check / Provider 已就绪;预标注回流、影子、蒸馏触发器未动工。

## ② 双引擎互证仲裁:把"知道自己不知道"做成机制

**创新是什么**:同一场景跑两个独立引擎——**VLM(语义/逻辑判定)+ AnomalyDINO(外观异常,免训练)**——并对结果做仲裁:
- 两引擎一致 → 出结论;
- 分歧 → 强制 **UNCERTAIN**,转人工,不猜。
能力分工:外观缺陷(划伤/污染/破损)归 AD 引擎,逻辑性错误(漏装/错装/顺序)归 VLM。这是把 2025–2026 学术共识(免训练 AD 强外观弱逻辑、VLM 强语义弱外观)落成产品机制,而不是停留在论文里。

**为什么是代差**:

| 对照 | 它的做法 | 代差点 |
|---|---|---|
| Ultralytics | 单模型出置信度,没有"我不知道"这个输出态;低置信照样给结论 | UNCERTAIN 是一等公民判定态,分歧即触发,而非可调阈值 |
| 海康 | 告警不带仲裁语义,误报靠人盯;AD 与检测各自独立产品 | 双引擎互证在同一判定链内闭环,UNCERTAIN 直通人工队列(告警中心) |
| 商业平台 | VLM 判错风险有公开证据(Nature Sci. Reports 2026:9 个 SOTA VLM × 5 领域系统对比),但商用产品普遍不做互证 | 我们用第二引擎把 VLM 的幻觉过杀(实测 1/6,见 [V0-SMOKE](V0-SMOKE.md))拦在人工复核前 |

**已有地基**:
- UNCERTAIN 判定态 + 转人工纪律已写进代码与设计(禁用未验证场景拒绝提交,判定锁低温 0.1,ADR-002 修订);
- AnomalyDINO(anomalib,Apache-2.0)选型完成:零训练、1–8 张 OK 图可用,1-shot MVTec ~96.6 vs PatchCore 83.4 AUROC(调研数据,见 [RESEARCH-UPGRADE §3](RESEARCH-UPGRADE.md));
- 评测工具雏形(`tools/eval_gloves.py` 等)可量化双引擎分工正确率。

**落地任务**:T3(AnomalyDINO 接入 + 仲裁分支实现与测试)、T2(回归集上验证分工)、T9(UNCERTAIN 进告警中心人工队列)。

**状态**:**半成品**——仲裁纪律(UNCERTAIN 转人工)已落地;AnomalyDINO 第二引擎未接入。

## ③ 回归集即合同边界:能力边界卡取代"99% 准确率"

**创新是什么**:每个场景交付时附一张**能力边界卡**:该场景在固定回归集上的**实测一致率/漏报/误报 + 复跑命令**。合同写的是"在 X 回归集上复跑 `python tools/eval_*.py` 得到一致率 ≥Y%",而不是"准确率 ≥99%"。指标可复算、可复核、可对质——回归集就是合同的技术边界。
配套纪律(已写入设计):评测集没建好,不对客户承诺任何准确率数字;向导末屏固定文案"本工具验证的是一致性,不是准确率;正式指标需按影子模式运行 ≥2 周"。

**为什么是代差**:

| 对照 | 它的做法 | 代差点 |
|---|---|---|
| Ultralytics | 给的是 COCO mAP 等公开基准数字,与"你的场景在你的数据上的表现"无关 | 边界卡锚定自建回归集(含现场多光照),数字随交付物走 |
| 海康 | 验收按点位抽检,口径不透明;换固件/换包后指标漂移无凭证 | 复跑命令 + 版本化回归集,任何一方可当场复算 |
| 商业平台 / 行业通病 | "准确率 ≥99%" 写进合同,是合同纠纷的主要来源(见《工业视觉AI平台技术方案》§0.6) | 把不可证的承诺换成可复算的边界,纠纷成本归零 |

**已有地基**:
- 评测工具:`tools/eval_gloves.py`、`tools/make_eval_set.py`、`tools/probe_first_article.py`(V0-SMOKE 实测执行过:手套 14/14 一致、首件 5/6 含 1 例幻觉过杀)——手套 14/14 vs 首件 5/6 这组数字本身就是第一张能力边界卡的素材;
- MVTec AD 2 定为公开标尺(学术用途限制已声明,自建业务集为准);
- **`visual/regress.py` 已存在并落地(2026-11-03)**:manifest 清单跑分、`--against` 对比出回归/改进清单;尚缺固定回归集入库与能力边界卡产物。

**落地任务**:T2(回归集基建,光照治理第 3 层"多光照评测集"在此落)、T7(评测 UI 化,冒烟自测向导)、T9(误报复核固定抽 N 条自动回流回归集,防腐化)、T20(每个蒸馏版必须过回归集才可发布)。

**状态**:**半成品**——评测工具链已落地;固定回归集、一键对比、边界卡产物未成。

## ④ 从纸到线:作业指导书 → DSL → 圈选 → 冒烟 → 影子 → 启用

**创新是什么**:把"上线一个 SOP 场景"从编程项目压成一条流水线:
**上传作业指导书(文字+照片)→ LLM 编译出步骤序列草稿(锁付类→foreach+obj_state;取放类→hand_dwell;检查类→vlm_check)→ Grounded-SAM2 文本圈选微调区域("描述即圈选")→ 冒烟自测(一致性×5 + 真值核对 / 回放比对)→ 影子模式 → 启用**。
判定上移语言层:换型号改一句提示词,相机挪位/光照变化对 `vlm_check` 无感;LLM 出错稿是常态,验证关卡(一致性+回放比对)是强制门,不省。

**为什么是代差**:

| 对照 | 它的做法 | 代差点 |
|---|---|---|
| Ultralytics | 用户要会写训练脚本、画框、调参;"配置"就是代码 | 从纸面文档直接编译出可运行草稿,普通用户只做确认 |
| 海康 | 算法配置在自家封闭工具里,换产品要厂家上门 | 编译+圈选+冒烟全程自助,验证关卡替用户把关 |
| 商业平台(AI-SOP 参考项目) | 步骤定义=坐标+时间窗,绑死产品与相机位 | 判定上移语言层;区域圈选由文本驱动;影子模式是上线必经关 |

**已有地基**:
- 设计稿完成:[SOP-COMPILE](SOP-COMPILE.md)(编译管线、模板库兜底=装配骨架参数化、泛化极限如实声明);
- `vlm_check` 已实现并过测试(编译产物的第一类原语);
- 冒烟自测探针已有(`tools/probe_*` 系列);禁用场景拒绝提交的验证纪律已实现;
- Grounded-SAM2(Apache-2.0 系)+ OWLv2(CPU 兜底)选型完成;X-AnyLabeling(GPL-3.0,仅独立桌面工具)→ CVAT(MIT)标注链路已定;
- 影子模式与发布/回滚 = R6/R7(未动工)。

**落地任务**:T5(模板库,编译的兜底骨架)、T10(标定向导=文本圈选落地)、T7(冒烟自测向导 UI)、T16(影子→发布闭环)、T22(SOP 编译器,规划池)。

**状态**:**半成品**——SOP-COMPILE 已设计、vlm_check 已落地;编译器、文本圈选、影子链未动工。

## ⑤ 告警自动引用规程条款:告警可申诉、可审计

**创新是什么**:告警不止"检测到违规",还要**自动引用它违反的规程条款**:
- 第一层(近期,抄 Frigate GenAI 机制):事件缩略图发给 VLM 生成"发生了什么/依据什么",富化进告警卡片——**富化只做解释,不进判定链**(可解释性≠判定义务);
- 第二层(远期,MonitorVLM 两段式):违规视频 → 条款检索 → 自动映射到具体 SOP/监管条款编号,飞书卡片直接带条款原文与深链。
处理人收到的是"违反《XX 作业指导书》第 X 条 + 证据缩略图",不是一张裸截图。

**为什么是代差**:

| 对照 | 它的做法 | 代差点 |
|---|---|---|
| Ultralytics | 只出检测结果,告警语义全靠下游自建 | 条款映射是我们 DSL(规则指纹→条款)的天然产物 |
| 海康 | 告警卡片为通用安防语义,无企业规程概念 | 条款库与场景 DSL 绑定,条款可版本化 |
| 商业平台 | Frigate GenAI(MIT)已做"为什么发生"的解释,但止步于自由文本;合规报告靠人工撰写 | 我们把解释锚定到结构化条款,告警→申诉→审计一条链 |

**已有地基**:
- Frigate GenAI 机制已调研透(事件 schema、去抖参数、富化链路;借鉴思路不引入依赖,检测仍走本地小模型,见 [RESEARCH-UPGRADE §7.1](RESEARCH-UPGRADE.md));
- MonitorVLM(arXiv 2510.03666)"条款检索+视频判定"两段式已调研;
- Provider 层现成(V1 纵切片,glm-5.3-flash 富化零新增依赖);R5(飞书推送)已并入 V7。

**落地任务**:T9(告警中心:富化层 + 飞书卡片先行)、T24(条款映射,规划池,依赖条款库与 DSL 条款编译链)。

**状态**:**规划**——机制已调研,实现未启动。

## ⑥ 视觉 + 声学双模态 SOP:声学工步签名当状态机事件源

**创新是什么**:SOP 状态机的证据不只来自视觉。人工装配工步有声学签名(拧/敲/锯的声纹差异),把**声学工步分类作为状态机的旁路事件源**:
- 麦克风级成本,无视觉遮挡问题(手被工件挡住时,声音仍在);
- 与视觉证据**对账**:视觉判"插接完成"与声学判"压合声"同时命中才确认步骤,单一模态存疑时降级 UNCERTAIN;
- 与创新 ② 同构:双模态互证,分歧转人工。
学术依据:TU Wien Fink 2024《Make some Noise: Acoustic Classification of Manual Work Steps》(工步声学分类可行);PSR 任务定义(TU/e Schoonbeek 2025)提供"步骤是否正确完成及顺序"的评测框架。

**为什么是代差**:

| 对照 | 它的做法 | 代差点 |
|---|---|---|
| Ultralytics | 纯视觉,无音频通道概念 | 状态机事件源是抽象接口,声学只是多挂一路 |
| 海康 | 安防产品线以视频为主,音频仅拾音不做工步理解 | 工步级声学签名 + 视觉对账是产线级新组合 |
| 商业平台 | Retrocausal/Invisible AI 全部依赖第一视角视觉硬件 | 麦克风是产线上最便宜、最无隐私争议的传感器 |

**已有地基**:
- 论文调研完成(TU Wien 2024、PSR 2025、EgoProceAssist 2025,见 [RESEARCH-UPGRADE §1.2](RESEARCH-UPGRADE.md));
- SOP 状态机证据接口天然支持旁路信号挂载(evidence 条件即事件);
- llama.cpp `libmtmd` 统一图/音/视频输入,端侧通道现成;
- 目标场景已锚定:W6 拆包刀具/拆封条工步。
**诚实边界**:学术成熟度一般(非顶会主会主推方向),先做 ≤5 步小 SOP 的 1–2 工位 PoC,**不进承诺排期**。

**落地任务**:T23(声学 PoC,规划池;前置:状态机运行时稳定 + W6 场景可配)。

**状态**:**规划**——调研完成,PoC 未启动。

## ⑦ 证据链即审计资产:可复算的判定过程,直交 IATF 16949

**创新是什么**:每次判定不止存结果,存**证据包**:原始帧/录像切片 + 判定 JSON + 命中的规则 DSL + **规则指纹**(规则哈希,证明"当时用的是哪版规则")+ 全链哈希与签名。审计(如 IATF 16949 过程审核)时交付的不是截图集,而是一包**可复算**的判定过程:拿证据包 + 对应版本引擎,能复现当时结论。
与许可台账(ADR-03)同源:模型、规则、数据的版本指纹登记在案,审计追溯时"哪个模型、哪版规则、什么数据"三问皆有据。

**为什么是代差**:

| 对照 | 它的做法 | 代差点 |
|---|---|---|
| Ultralytics | 输出图片/视频标注,无证据封装概念 | 证据包是平台产物,不是模型产物 |
| 海康 | 录像回放 + 告警截图,规则版本不可考("当时跑的是哪版算法?"答不上) | 规则指纹让"判定依据"本身可归档 |
| 商业平台 | 合规报告人工编写,证据与判定脱节 | 证据包机器可验:哈希核对 → 引擎复算 → 结论对账 |

**已有地基**:
- 证据哈希已有(见 [PLATFORM-GAPS §一](PLATFORM-GAPS.md):"证据哈希有,签名/策略未做");
- ZLMediaKit 录像切片选型已定(R3);
- DSL 规则即文本文件,天然可哈希成规则指纹;
- ADR-03 许可台账纪律已立(台账本身未建,挂 T19)。
**未做(如实)**:签名、保存/清理策略、审计包导出格式。

**落地任务**:T14(视频留证 + 证据签名/保存策略 + 审计包导出)、T19(离线包/签名模型包 + 许可台账)。

**状态**:**半成品**——证据哈希已落地(约一半);签名、策略、审计包导出未做。
