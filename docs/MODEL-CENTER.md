# 视觉应用：统一入口

给现场用户集中查看已登记模型、试推图片，并直接进入标注工作台。首版不要求填写模型路径、类别表或推理参数。

## 三步开始

1. 打开「视觉应用」，选择已安装模型。类别自动显示；文件存在不代表独立评测通过。
2. 点「试一张」上传图片，查看检测框与本次完整请求耗时。没有检出会明确显示，不自动判定合格。
3. 点「用于标注」自动创建同类别项目，或打开兼容的已有项目补充样本。

试推使用按需CPU子进程，完成后退出；试推图片不进入真值库。模型不可用时显示原因，不会自动下载未知权重。viewer只读，不可试推或创建项目。

## 当前范围

模型来自服务端已登记的ONNX引擎，包括现有安全帽和已启用工位模型。当前只支持已有YOLO检测适配契约，不接受任意PT/pickle文件。

“补充样本”只是进入已有项目标注；不是已经训练增强。后续训练、评测、影子、发布会由一个任务串联，但生产切换仍要求通过检查，保留旧版本。当前页面不提供无实现的训练或发布按钮。

## 零配置交付规则

- 默认选择任务兼容的底座、类别映射和输入契约；有多个同样可行的业务方案才要求用户选。
- 新场景“一键应用”应后台串联数据检查→隔离训练→独立评测→影子候选，不把机器伪标签当验证真值。
- 旧模型“增强”必须同时回放旧能力与新样本，保留不参与调参的测试集；不以只看新样本提升为发布依据。
- 无足够独立来源组时直接说明“需要另一拍摄批次”，不要求用户手填随机种子或技术阈值。
- ROI、相机、设备信号和物理标定属于现场事实，不能由默认参数猜测；使用画面框选和设备选择完成。

## 统一应用体验

不再设置三个并列的模型/场景/部署中心。用户以业务应用为主对象，入口为「视觉应用」；模型是内部可复用资源，部署是该应用的运行状态。

目标主路径为准备样本→验证效果→应用到相机；每个阶段只保留一个主要下一步操作。模型元数据、优化器、版本指纹、运行provider等下沉高级信息。已部署应用提供补样本增强、状态和回退入口。

首版实际仅具备已登记模型试推、自动创建同类别标注项目、打开已有项目补样本；没有实现的训练/发布不显示可执行按钮。后续应用实体需绑定项目、场景配方、固定模型版本与工位部署，不用临时名称替代版本关联。
