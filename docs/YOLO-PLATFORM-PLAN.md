# YOLO 实时平台交付路线

2026-11-03：按用户新要求，YOLO 承担主要实时目标/缺陷识别，规则和设备信号负责工艺判定，VLM 只作可选辅助。不换已有 YOLO，不以没有客户数据阻塞通用平台开发。

## 用户完整路径

选 SOP/质量/安全场景 → 导入图片、标签或视频 → 自动检查类别与数据问题 → 预标注/人工复核 → 固定数据版本 → 训练或导入批准模型 → 独立评测 → 工位影子 → 发布 → 监控与回滚。

每个环节显示状态、问题和下一步；失败保留已有成果。未经复核的导入标签不变成人工真值，导入成功不代表数据可训练。

## 专用能力按任务实现

| 类别 | 场景 | 主实现 | 数据策略 |
|---|---|---|---|
| SOP | 取料/在位/缺件/多点装配/标签到位 | YOLO定位 + 跟踪/区域/状态机 + 设备信号 | 通用物体底座；用户零件类别导入与微调 |
| SOP | 取出与放回、复杂装配动作 | 检测/姿态 + 时序模型旁路 | 公开动作数据作初始化，用户动作片段复核 |
| 安全 | 安全帽/手套/反光衣/口罩/护目镜 | PPE专用YOLO + 人体关联 + 时序过滤 | 公开PPE基线 + 客户困难样本 |
| 安全 | 烟/火 | 专用YOLO + 时序过滤 | 公开烟火数据与负样本；原不合格权重不发布 |
| 安全 | 手机/吸烟/禁区/倒地/聚集/离岗 | 小目标YOLO + 姿态/跟踪 + 场景规则 | 公开候选逐类验证，不将物体出现直接当行为 |
| 质量 | 包装破损、表面缺陷、缺件 | YOLO检测/分割或专用异常检测 | 公开缺陷数据作基线；客户产品配方与缺陷数据 |
| 质量 | 标签内容、数显读数 | 检测定位 + OCR + 格式/范围校验 | 公开OCR底座 + 客户版式与困难样本 |
| 质量 | 指针仪表 | 表盘定位 + 关键点/角度 + 标定 | 表盘模板/量程标定 + 独立读数真值 |
| 质量 | 尺寸、间隙、色差 | 标定/光学/几何或色彩算法 | 标准件与标定资产，不以YOLO框代替计量 |

## 公开资源先行

先尝试可靠预训练权重；不合格则用公开数据训练当前YOLO小模型。用户数据用于特定产品/现场适配，而不是通用功能开发的前置条件。模型、训练代码、数据来源分别记录；公开可下载不自动代表整套可商用。

已核对入口：
- Construction-PPE：https://docs.ultralytics.com/datasets/detect/construction-ppe （11类PPE，含独立测试划分）。
- D-Fire：https://github.com/gaia-solutions-on-demand/DFireDataset （烟/火YOLO标注、负样本、预训练模型入口；集合声明CC0，第三方图像来源另记录）。
- SH17：https://github.com/ahmadmughees/sh17dataset （17类与YOLO权重；数据CC BY-NC-SA 4.0，先列研究候选，不列默认交付资产）。

VLM 不在实时报警必经链路；可用于标注建议、离线规则草拟、未知样本说明。训练/导出/评测均按任务启动，完成或取消后退出。不做多分辨率穷举；固定首个目标输入，报告真实P95、漏检、误报和未知。


## 行业覆盖清单（用户追加，不代表已实现）

- 工业/制造：PPE、烟火、人员区域、物料计数、在位/缺件/错装、表面缺陷。
- 锂电：极片表面与涂布缺陷、极耳/焊点外观、装配在位、标签与工件追溯。厚度、内部焊接与绝缘须专用成像/设备测量。
- 汽车电子：PCB与元件缺失/偏位、连接器与端子、焊点外观、线束装配、壳体缺陷、OCR追溯。
- 仓库仓储：货物/托盘计数、货位占用、堆垛倾斜、通道堵塞、叉车人车混行、装卸异常。
- 翻包仓库：暂按拆包/倒料/换包/复包理解；包装在位、开封/倒料/复包步骤、残留物与异物。
- 机械臂：工件定位、抓取前后有无、放置偏位、漏抓/掉落、人员进入作业区，结合机器人IO；抓取坐标另外标定或深度测量。
- 物流：包裹计数、破损、标签OCR/条码、错分漏分、传送带堵塞、装车核对。

以上按检测/分割/跟踪/OCR/姿态/时序共用底座建立场景包。每包必须含模型指纹、类别、输入契约、规则、独立样本指标、延迟、适用条件与失败样例。不能用同一通用模型改名充当行业模型完成。

## 常用 SOP 模板目录（T36 子任务）

| 阶段 | 必须覆盖的流程 | 主要证据 |
|---|---|---|
| 开工准备 | 工单/产品配方、人员与PPE、工具/治具到位、清场与首件确认 | MES/扫码、YOLO、工装IO、人工首件审批 |
| 上料取料 | 取料、选料、数量、顺序、防错料、防混料 | 料盒区域+手/物体跟踪、类别、扫码 |
| 工件定位 | 到位、方向、正反面、治具夹紧 | 检测/关键点/角度、夹具传感器 |
| 装配连接 | 放件、插接、卡扣、压装、压合、线束走线与端子到位 | YOLO/分割+区域关系、力位移/到位信号 |
| 紧固作业 | 多孔锁付、顺序、漏锁、扭矩/角度合格 | 孔位关联+工具ID/扭矩枪结果，不由手停留推断合格 |
| 加工施作 | 点胶/涂胶、焊接、清洁、擦拭、灌装/倒料 | 专用视觉+轨迹/覆盖、设备计量/工艺参数 |
| 标识包装 | 贴标、扫码绑定、附件齐套、装箱数量、封箱、称重 | YOLO/OCR/条码、秤、产品SN |
| 检查下料 | 自检、复检、返工、NG隔离、下料、计数 | 明确检测项、人工确认、设备结果、工件追踪 |
| 全流程约束 | 漏步、错序、超时、重复操作、工件串件、跨周期旧证据、暂停/恢复 | 状态机、周期/SN身份、TTL、审计 |

现有引擎已具备区域/顺序/超时/多点/信号基础；上表完整模板、设备接线与专用识别尚需逐项落地。每个模板必须可编辑ROI/类别/阈值/信号映射，并有正常、漏步、错序、遮挡、断流和设备掉线的回放测试。VLM不能作为实时完成判据的默认必经步骤。


## 统一模型中心（T34/T35 产品入口）

统一入口，不做一个塞满参数的页面。分为模型库、训练任务、评测报告、部署实例四个页签；从行业场景卡进入时自动筛选相关模型。

- 模型资产：名称、不可变版本、SHA256、任务类型、类别表、输入/输出/预处理契约、权重/数据/代码来源、许可记录、支持适配器与运行环境。
- 试用与评测：上传图片/片段试推；训练集与独立验证集分开；每类指标与错误样本、实际硬件P95；未测试显示未测试而不是0或默认合格。
- 训练：选择固定数据版本和基座，预检资源后按需启动隔离worker，可取消，有日志；UI默认简化，优化器等放高级配置。
- 发布：将固定模型版本、类别映射、ROI、阈值、规则、信号/标定版本组成发布包；绑定明确工位；影子→审批→生产→回滚。模型库“默认版本”变化不应静默替换运行工位。
- 运行：显示实际加载版本/设备/provider、路数、延迟、显存、错误、冷启动、空闲释放；模型资产本身不启动常驻服务。

模型参数、场景规则和工位部署配置分层保存：同模型可复用到多个场景，同场景可有多个工位参数；改一个工位不污染所有实例。

参考已核对的官方产品设计（2026-11-03）：Ultralytics模型页分Overview/Train/Predict/Export/Deploy；Roboflow Workflows以模型、逻辑、集成节点编排；MLflow以版本、血缘、别名和标签管理模型。借鉴流程，不默认引入这些服务或Docker依赖。

## 工程约束

新增业务模块目标200–400行，超过500行先审查职责，超过600行须拆分或记录明确理由；不靠压缩排版减少行数。已有server.py等大文件按功能迁移到router/service/store，不继续堆业务，也不在无关改动中全量重构。

注释解释单位、坐标系、状态变化、不变量、并发/资源生命周期和失败策略；公开接口有docstring与类型，避免逐行重复代码。路由只负责输入/权限/响应；存储、模型适配、任务调度、评测、发布独立模块。新边界必须配非法输入、权限、取消/恢复、资源释放测试。Web一次主桌面交互验收，后端聚焦测试后整批回归。
