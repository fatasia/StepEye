注意:两段视频全部为裸手作业,**没有 PASS 正样本**,本集只测违规方向(漏报违规是 EHS 最危险的错误)。

## 三、首件两步判定(仿真装配,真值已知)

样本:仿真工位渲染 3 OK + 3 NG 参考图,6 张待检(真值 PASS×3 / NG×3,状态由渲染器决定,无标注歧义)。

| 指标 | 结果 |
|---|---|
| 准确率 | **5/6 = 83%** |
| 错误 | 1 例**过杀**:真值 PASS 被判 NG(conf 0.9),理由「第一排最右侧星星缺失」——模型把螺丝上的装饰线幻觉成缺失缺陷 |
| 延迟 | **P50 137s,max 390s**(7 图上下文 × 两步链式调用) |

**延迟结构分析**(实测对齐):单图 7s → 7 图约 50s/次 × 2 次调用 ≈ 100–140s,基本线性于图像 token 量;
长尾(max 390s)是共享端点排队。首件检业务本身低频(每班次几件),分钟级在容忍内,但 **V3 队列必须异步 + 并发受控**;
优化空间(两步合一、参考图精选、ROI 裁剪)待 V6 评测后逐项验证。

## 四、跨调用稳定性问题与修复

**实测发现**:同一张 eval_03(评测时 NG conf 0.95)在另一次调用中返回 UNCERTAIN——15 次调用中出现 1 次跳变。
**修复**:判定调用温度锁 0.1(`ProviderConfig.temperature`,ADR-002 修订)。
**验证**:修复后同图连跑 3 次,3/3 一致 NG(0.85/0.9/0.9)。

## 五、结论与红线

1. coding 端点 + glm-5.3-flash 可支撑拍照即检;手套类单图判定质量足够进入演示场景。
2. 首件两步判定可用但有幻觉过杀(1/6),**V6 固定样本集回归是提示词迭代的必要基础设施**。
3. **仍然没有真实产线准确率**:14 帧无正样本 + 6 张仿真件 ≠ 准确率承诺。对客户只讲链路与演示,不讲数字。
4. 下一步:补带 PASS 正样本的自拍样本(戴/不戴手套各若干)、V6 固定回归集、V3 定点相机上传脚本。
