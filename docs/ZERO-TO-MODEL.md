# 从 0 到运行:普通用户做出一个可用的"视觉模型"

> 2026-11-02 产品设计。核心理念:**普通用户不做训练,做选择与拍照**。
> 两条路线各自有一套"从 0 到运行"的旅程,终点都是「默认禁用,验证后才启用」。

## 一、拍照即检路线(大模型):10 分钟旅程

```
选场景模板 → 拍参考图 → (改提示词) → 冒烟自测 → 启用 → 日常运行与迭代
```

| 步 | 用户做什么 | 系统做什么 | 现状 |
|---|---|---|---|
| 1 | 从模板库选场景(手套/破损/烟火/首件对照/表盘…) | 带出默认提示词与判定 JSON 格式 | **模板库待建**(V9);现可手写 YAML |
| 2 | 每场景拍 ≤3 张 OK + ≤3 张 NG 手机照,上传 | 自动缩放/存档为参考图 | 参考图目录机制已有;**上传引导 UI 待做** |
| 3 | 可选:改判定口径(界面文本框,所见即所得) | 提示词版本化,改一次存一版 | **待做**(V2/V9) |
| 4 | **冒烟自测**:再拍 3–5 张现场照点「验证」 | 跑 5 次一致性(同图判 5 遍)+ 真值核对页 | 探针工具已有(tools/probe_*);**向导 UI 待做** |
| 5 | 一致且与预期相符 → 点「启用」 | 场景 enabled=true;不一致 → 保持禁用并提示改提示词/换参考图 | **纪律已实现**(禁用场景拒绝提交) |
| 6 | 日常:巡检拍照/定点相机自动上传 | 队列判定、UNCERTAIN 转人工、告警闭环 | 纵切片已通;告警闭环属 V7 |

**关键设计纪律(已写入代码)**:验证过的组合才默认启用;判定锁低温;UNCERTAIN 转人工;评测集没建不承诺准确率。

## 二、实时规则路线(SOP/安全):30 分钟旅程

```
选工位模板 → 画区域 → 摆参考状态采集 → 冒烟回放 → 启用
```

| 步 | 用户做什么 | 现状 |
|---|---|---|
| 1 | 选工位类型(装配/翻包/巡检岗),带出 zones/steps 模板 | 模板待建;可复制 demo YAML |
| 2 | 在画面上**拖框画区域**(替代手写坐标) | **标定向导/区域编辑未做(界面已留禁用占位)**——这是普通用户的最大门槛,优先级最高 |
| 3 | 把实物摆到"正确状态",点「采集参考图」 | **API 已实现**(POST /calibrate),差向导 UI |
| 4 | 用一段回放视频离线跑一遍,看判定是否符合预期 | `python -m visual run --video` 已实现 |
| 5 | 启用实时监控 | 已实现 |

安全类(无人值守/聚集):画一个「岗位区」+ 选一条安全规则(区域无人 >N 秒 / 人数 ≥M)即可,
无需参考图——执行器本轮已落地(`visual/safety.py`),**运行时接线待做**(下一轮:runtime 喂事件 + tick + WS 推送)。

## 三、给"完全不懂"的用户的兜底路径(设计约定)

1. **模板库优先于自由配置**:每季度按客户现场沉淀模板(锂电翻包/仓储充电区/装配工位),用户 90% 情况只做选择。
2. **一切配置可被"验证"关卡拦住**:没有冒烟自测通过,配置不允许上线(拍照即检=一致性+真值核对;实时=回放比对)。
3. **失败要可解释**:验证不通过时,界面要说"哪一步不对、下一步做什么"(如"5 次判定有 2 次不一致→请改用更明确的提示词或加参考图")。
4. **准确率诚实**:向导最后一屏固定文案——"本工具验证的是一致性,不是准确率;正式指标需按影子模式运行 ≥2 周"。
